# Batch 1 — measurement qualification and first integer instruction table

This directory contains the first deliberately small execution batch from the roadmap. Its job is not to publish a universal Haswell instruction table. Its job is to prove that this DUT, this compiler, and this harness can tell apart a timer, a loop, a real dependency chain, and independent work.

## Why these tests

`add_latency` is a true dependency chain with 128 static ADD instructions in its generated body. `imul_latency` is a longer one. `xor_break` and `and_zero_control` have the same final value but differ in whether the zeroing instruction must wait for a prior multiply result. The `add_throughput_1/2/4/8` rows contain 128 ADD instructions per body while sweeping independent chains. The expected story is that more streams eventually stop improving cycles per ADD; that plateau, not the one-stream result, is reciprocal throughput.

The `page_state_probe` is intentionally separate from the register tests. It validates the words `warm`, `cache_evicted`, and `page_cold` using actual page reads and page-fault deltas. It must never be used to call a register-only ALU loop “page cold.”

## Files

- `src/batch1.cpp` — the measurement binary. Its header and every non-obvious block explain its purpose, expected behavior, failure conditions, and sources.
- `scripts/run_batch1_on_dut.sh` — builds exactly one binary, records machine/disassembly/hash evidence, randomizes the retained-case order, and fails rather than overwriting a result directory.
- `results/` — local copies of DUT raw output and the finished article are placed here after collection.
- `article/` — the finished Batch 1 article and its static/interactive visuals are placed here after analysis.
